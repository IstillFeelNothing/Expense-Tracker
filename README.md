# Трекер витрат

Консольна програма на Python для обліку особистих витрат. Дані зберігаються локально у файлі `expenses.json`.

## Можливості

- додавання витрати: сума, категорія, дата, опис;
- перегляд усіх витрат у вигляді таблиці;
- редагування та видалення витрати за ID;
- статистика за сьогодні, за останні 7 днів, за вибраний місяць або рік: загальна сума і розбивка за категоріями (від більшої суми до меншої).

Правила введення:

- **Сума** — додатне число, до 2 знаків після коми, не більше 1 000 000. Кома і крапка як роздільник обидві підходять (`250,50` або `250.50`).
- **Категорія** — до 50 символів. Регістр і зайві пробіли не враховуються. Якщо залишити поле порожнім, буде записано «без категорії».
- **Дата** — `ДД.ММ.РРРР` або `РРРР-ММ-ДД`. Порожнє поле означає сьогоднішню дату. Дата не може бути в майбутньому або раніше ніж 100 років тому.

## Вимоги

- Python 3.10+ (розроблялося на 3.14)
- Для запуску програми сторонні бібліотеки не потрібні. Для розробки потрібні `pytest`, `ruff` і `mypy` (група `dev` у `pyproject.toml`).

## Запуск

```bash
python main.py
```

Програма відкриває меню, де дію обирають цифрою (`0` — вихід). Файл `expenses.json` створюється в поточній робочій директорії під час першого збереження. Ctrl+C або Ctrl+D (Ctrl+Z на Windows) завершують роботу без помилки.

## Тести

```bash
pip install --group dev   # потрібен pip 25.1+
pytest            # тести
ruff check .      # лінтер
ruff format .     # форматування
mypy              # перевірка типів (strict)
```

Налаштування всіх інструментів лежать у `pyproject.toml`. Запускайте команди з кореня проєкту.

## Архітектура

Шари залежать один від одного лише в одному напрямку:

```
main.py ──► app.py (ExpenseApp) ──► view.py (ConsoleView)
                    │
                    ├──► calculator.py      (періоди, фільтрація, підсумки)
                    ├──► validator.py       (розбір і перевірка введення)
                    └──► repository.py (ExpenseRepository)
                                 │
                                 ▼
                     storage_protocol.py (StorageProtocol)
                                 ▲
                                 │ реалізує
                         json_storage.py (JSONStorage)
```

| Модуль | Відповідальність |
|---|---|
| `main.py` | Точка входу: створює `JSONStorage`, `ExpenseRepository`, `ConsoleView` і `ExpenseApp` та передає їм залежності. |
| `app.py` | `ExpenseApp` — цикл меню і сценарії (додати, редагувати, статистика). Поточну дату отримує через функцію `today_fn`, тому в тестах її можна підмінити. |
| `view.py` | `ConsoleView` — усе введення й виведення: меню, таблиці, форматування сум (`1 234,50 грн`) і дат. Функції `input`/`print` передаються в конструктор, тож тести можуть їх замінити. |
| `expense.py` | `Expense` — незмінний (`frozen`) dataclass. Сума зберігається як `Decimal`. Методи `to_dict` / `from_dict` перетворюють витрату на словник і назад з перевіркою даних. |
| `validator.py` | Розбирають і перевіряють суму, дату та категорію. При помилці кидають `ValidationError`. |
| `calculator.py` | Чисті функції: межі періодів (день, тиждень, місяць, рік), фільтрація за періодом `[start, end)`, загальна сума, групування за категоріями (з урахуванням українського алфавіту при сортуванні). |
| `repository.py` | `ExpenseRepository` — CRUD над витратами в пам'яті, призначає ID (`last_id`). Перед роботою потрібно викликати `load()`. Кожну зміну спочатку записує у сховище, і лише після успішного запису оновлює стан у пам'яті. |
| `storage_protocol.py` | `StorageProtocol` (інтерфейс сховища), тип `StorageData` та винятки сховища. |
| `json_storage.py` | `JSONStorage` — читання й запис JSON. Запис атомарний: дані пишуться в тимчасовий файл, а потім замінюють основний. Пошкоджений файл перейменовується на `expenses_corrupted_<час>.json`, і програма продовжує роботу з порожнім сховищем. |

Формат файлу даних:

```json
{
    "last_id": 2,
    "expenses": [
        {"amount": "250.50", "category": "їжа", "description": "Обід", "date": "2026-11-14", "id": 1}
    ]
}
```

### Тести

Тести лежать у `tests/`, для кожного модуля окремий файл. `tests/fakes.py` містить `FakeStorage` — реалізацію `StorageProtocol` у пам'яті, яка вміє імітувати помилки читання, запису та пошкоджений файл. З нею репозиторій і застосунок можна тестувати без файлової системи.
